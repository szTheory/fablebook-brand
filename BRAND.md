# Fablebook brand

Version 2.0, November 10, 2026. This is the complete text of the brand book (`fablebook-brand-book.html`), page by page, for people and AI assistants. The same rules as structured data are in `brand.json`; colors and type values in `tokens.json`; every file is explained in `assets/README.md`.

**Read this first.** A UI catalog for Phoenix LiveView. Mock up all of your user flows and preview them with realistic data so you can quickly iterate to perfection. For developers, designers, product people and LLMs. Light is the default theme and dark is a full theme. The logo is the word with its f ribbon, with no shape behind it and no tagline; the gilt appears only in the logo, the docs and the social card, never in the UI catalog. Every marker (Edited, Gap, Waived) is a word first and a color second. The contrast pairs have stable ids (body, descriptor, caption, application-copy, hero, link, focus, artwork) in both themes.

## The idea

**Why a bookmark on the f**

Most UI work is judged on the happy path. The empty first visit, the failed payment and the client name that runs across three lines are where screens let users down, and finding them means clicking through the whole app. Fablebook shows each as a named scenario to open, compare and link to, so a team sees the whole user flow.

The mark is the first letter of the name, a lowercase f, whose stem becomes a bookmark ribbon with a swallowtail end, hanging below the baseline. The ribbon is the same shape the UI catalog uses to mark the current scenario. In the logo it is the one gilt piece: the place you’ve kept.

The f is the wordmark’s own f, from Schibsted Grotesk, cut once under the crossbar. Nothing in the mark is a shield, a lock or an eye. Fablebook helps people see what is there; it does not guard, watch or certify.

### App tile and favicons

The app tile and the 16 and 32 px favicons use a heavier f (weight 800 at 32 px, 900 at 16 px) that fills the tile from top to bottom. The ribbon runs out through the bottom edge and its notch is cut through the tile, so the tile is not a plain light letter on a rounded square. Below 16 px, do not use the mark.

### Browser tab

The browser tab follows the theme: `favicon.svg` is an Ink tile on a light device and a Paper tile on a dark one. The `.ico` has the light drawing only, because an ICO can’t change with the theme.

## Clear space and minimum size

Keep clear space on every side equal to the height of the letter b (its ascender), measured from the outermost edge of the logo. Nothing enters it: no text, edge or other logo. The square is that distance.

### On screenshots and photographs

- Place the logo on a calm area at least as wide as the logo and its clear space.
- Use the light drawing on a light area and the dark drawing on a dark one. If neither reads well, move the logo.
- Do not put a shape or a shadow behind it to make it read.

### Minimum size

|   | Screen | Print |
| --- | --- | --- |
| **Logo** | 14 px tall | 12 mm wide |
| **Tile, drawn for its size** | 16 px | Not specified |

On screen, the logo is never smaller than 14 px tall and the tile never smaller than 16 px. In print, never smaller than 12 mm wide.

### What the mark can be mistaken for

An f with a stem below the baseline can be read as ƒ, the function sign. Developers know it, and for a Phoenix library of function components it is an acceptable second reading. The name is also one letter from another well-known name, and a light f on a rounded square is a common app-icon pattern; the tile avoids it by running the ribbon through the bottom edge.

## Color: the three markers

### Ui catalog markers

**Three words, never the gilt.**

The UI catalog has three markers. Each is a word first; its color only backs the word up, and none of them is the gilt.

Edited, Gap and Waived are the only status words in the UI catalog. The Gap brick is kept apart from the gilt, so a gap never looks like the logo.

### What each means

Coverage

Describes a screen. Stays until someone covers the case.

**Gap**

Not covered yet: there is no scenario for it, and nobody has waived it.

**Waived**

Set aside on purpose, with your reason. It stays visible and counted.

Preview

Describes one preview. Gone when you restore the scenario.

**Edited**

Temporary: a control changed a value. Your code is untouched; Restore scenario puts the original back.

### The one ribbon in the ui catalog

The current scenario carries a small ribbon, the same shape as the logo’s. Inside the UI catalog it is Ink; on the docs site it may be gilt.

### About these ratios

Ratios are WCAG 2.2 contrast, computed from the hex values. A pair that passes here says nothing about a whole product built with it. Gilt on Paper is 3.4:1: enough for a shape, not for text. Hairline and Dim Line only divide; they are never the only boundary of a control.

### Never

- **Gilt** as text of any size on Paper or Card
- **Gilt Deep or Gilt Bright** as anything inside the UI catalog (use Ink or Vellum)
- **Hairline** as the only boundary of a control
- **Gilt, Gilt Deep or Gilt Bright** as a status or a warning

## Voice: the tone dial

**Plain: Fablebook says what the user is trying to do, what is on screen and what to do next, and never raises its voice.**

- The UI catalog: empty and error messages: 0 of 4 toward lively. “No scenarios yet. Add one to this story, or mark this kind of case as waived.”
- Docs and README: 1 of 4 toward lively. “Mount Fablebook as a dev route in Phoenix, then open it to see every screen in your app.”
- Release notes: 1 of 4 toward lively. “A story’s coverage now shows which kinds of case have a waiver and why.”
- Talks and social posts: 2 of 4 toward lively. “The empty screen is where most apps first let a new user down. Here is how to see it before they do.”

The voice never changes; the tone shifts with where the words appear. Fablebook is plain everywhere and a little livelier in a talk or a post. In the UI catalog it is never lively: a developer there is trying to find out why something looks wrong.

## Voice: this, not that

- Say: “Add a scenario for the empty screen.” Not: “Create a new variant.”
- Say: “This screen has no scenario for when saving fails.” Not: “Coverage gap detected in your design system.”
- Say: “Restore scenario” Not: “Reset your changes.”
- Say: “Fablebook shows your screens the way your users see them.” Not: “Fablebook makes your UI bulletproof.”
- Say: “Mount it as a dev route in Phoenix.” Not: “Seamlessly integrate Fablebook into your workflow.”
- Say: “Empty: new account, nothing sent yet.” Not: “Edge case 4.”
- Say: “Waived: this case does not apply to a read-only table.” Not: “Skipped.”
- Say: “No scenarios match this filter. Clear the filter to see all 38.” Not: “Oops! Nothing here.”

### Write for the people reading

- **Start from the user.** Say what they are trying to do and what they see before any term from the code.
- **Say what to do next.** Every empty and error screen ends with a step.
- **Name scenarios by what the user is going through.** A designer or product manager who didn’t build the screen should know what is on it without opening the code.

## Considered and not needed

**Mascot**

Considered, not proposed. A tool for working on a UI is trusted for being calm and exact, and a character pulls the other way.

**Patterns and textures**

The ribbon is the only graphic device. A pattern would compete with your UI in the canvas, which is the picture.

**Stock photography and illustration**

There is no honest photograph of “a screen when the save fails”. The real UI catalog says it better.

**A second typeface for the logo**

The wordmark and the interface are both Schibsted Grotesk; the book face, Literata, is for docs headlines only.

**Brand color in the UI catalog**

The UI catalog stays neutral so the app’s own colors are the only color on screen.

**Logo animation and sound**

Not defined in this edition. The UI catalog has no sound, and moving between scenarios is instant; see To review.

## To review

**Choices made in this edition that are easy to change**

1. **“UI catalog” is the one name.** The descriptor is “A UI catalog for Phoenix LiveView”, and the part you open is the same thing. “Workbench” is gone from the book.
2. **One word for each thing: scenario, case, story.** A scenario is one screen in one case; a case is what a user is going through (a first visit, nothing there yet, an error). “Case” replaces “situation”, which read as a synonym of “scenario”; “condition” is the alternative. “Story” is still the word for one screen; if user flows are your unit, it changes with the glossary and coverage map.
3. **Edited is set apart from Gap and Waived.** Edited is temporary, so it is a round outlined pill, listed apart from the two coverage marks. Gap is brick, not amber, which would read as gilt; Waived has a dashed outline. Meanings stay short until Fablebook is further along.
4. **The terminal prints the words gap and waived in color.** Gap is brick and waived is slate; both are written out, so the table reads without color. It is the one place brick appears in code.
5. **The book says screens, paths and cases, not “states”.** Scenario, story, gap, waived and edited are the product’s own words.
6. **Some audience promises are the owner’s wording.** Previewing user flows with realistic data, a scenario coverage map, personas, jobs to be done, component styles as structured text, and “test scenarios” and “styling” in your repository are not confirmed as shipped.
7. **“Domain language” replaces “canon”; no “draft”.** “Canon” came from the product’s notes; confirm the name there. There is no draft label: the UI catalog has only Edited, Gap and Waived.
8. **The ribbon is part of the f.** It is the f’s stem below one cut. A logo with a whole f and a ribbon beside it would state the initial twice.
9. **The name sits close to a very well-known one.** Fablebook is one letter from a famous social network, whose icon is a lowercase f on a rounded tile. The tile’s ribbon runs out through the bottom edge to break that. Name clearance was not searched.
10. **Gilt is a docs-and-logo color only.** The UI catalog has no accent. If it ever feels sterile, the ribbon on the current scenario is the first place to add gilt.
11. **Light is the default theme.** Docs, README and Hex render light by default, with a dark theme for dark devices. The UI catalog follows the device.

**Not checked:** Name and trademark clearance were not searched; the name was kept. Code samples follow the README and were not run. Logo legibility was checked on test sheets and by model readers, not with people. Contrast is computed for the pairs listed here, not for a whole product. Print color was not proofed. The favicon and tile were not checked on a real device or in Safari, and the 16 px tile still sits close to a plain letter on a rounded square.
